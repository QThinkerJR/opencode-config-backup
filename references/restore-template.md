## How to run this

Open this file in an OpenCode session and ask the agent to execute it. The agent must use a confirmation loop:

1. Read `manifest.json` and show a compact plan: target config directory, action counts, overwrites, `.restore-backups` copies, missing secrets, plugin installs, MCP authentication, and manual actions.
2. Run the restore helper in dry-run mode first:

   ```bash
   node tools/restore.mjs --bundle . --target "<config-dir>" --dry-run
   ```

3. Ask for confirmation with the `question` tool. Include options such as **Confirm restore**, **Adjust**, and **Cancel**. The tool also accepts free-form feedback. Apply feedback to the plan and re-run the dry-run until the user confirms.
4. Before applying, supply any missing secret labels in a temporary JSON file. Then apply using the exact plan hash shown:

   ```bash
   node tools/restore.mjs --bundle . --target "<config-dir>" --secrets "<secrets.json>" --approve "<plan-hash>"
   ```

5. Never leave a `<REDACTED:...>` placeholder in a live config file. The helper stages and asserts this before replacing a target.
6. Install server plugins, authenticate MCPs, and verify the result as described below.

## Guiding principles

1. **Runtime detection first.** Resolve the local OpenCode config directory with `opencode debug paths` (fallback: `$XDG_CONFIG_HOME/opencode`, else `~/.config/opencode`). Create it if missing. Never pass the home directory or a filesystem root as `--target`; the restore helper refuses those values.
2. **No writes without confirmation.** Dry-run, show the plan, accept feedback, repeat, then apply. The helper refuses to apply with a stale or missing plan hash.
3. **Back up before overwrite.** The helper stages the replacement, then copies the existing file/directory into `<config-dir>/.restore-backups/<timestamp>/` before replacing it.
4. **Idempotent.** Identical files and directories are skipped. Local plugin directories are replaced only when their content differs.
5. **Secrets are re-supplied, never printed.** Prefer `{env:NAME}` references and environment variables. For literal secrets, create a temporary JSON file outside the config directory mapping each `<REDACTED:label>` label to its value and pass it with `--secrets`. Do not paste secret values into the chat.
6. **Fail soft for network steps, fail closed for files.** A failed plugin download or MCP login is recorded and summarized; a missing secret or checksum mismatch stops the file restore.
7. **Tool-first, shell-second.** Use the restore helper for deterministic file work. Use shell only for plugin/MCP/auth commands and verification.

## Configuration directory

- Linux/macOS: `~/.config/opencode`
- Windows: `%USERPROFILE%\.config\opencode`
- `XDG_CONFIG_HOME` overrides the base on all platforms.
- The restore helper uses `OPENCODE_CONFIG_DIR` when set as the default target; otherwise `~/.config/opencode`.

The legacy `tui.json(c)` files are V1 client configuration. V2 uses `cli.json`; do not copy `tui.json` over an existing `cli.json`. If both are present in this bundle, restore `cli.json` only on V2 targets and let the V2 client migrate legacy settings when appropriate.

## Restore steps

### Step 1 — Read the manifest

Parse `manifest.json`. Group items by classification and report:

- items that will be created, overwritten (with `.restore-backups`), or skipped;
- secret references that need values;
- server plugins to install;
- TUI plugins already configured in `cli.json`;
- local plugin directories restored under `plugins/`;
- MCP servers needing OAuth or manual installation;
- auth providers that need `opencode auth login` or environment variables;
- warnings, especially V1 plugin API incompatibilities.

### Step 2 — Dry-run and confirm loop

Run `node tools/restore.mjs --bundle . --target "<config-dir>" --dry-run`.
Present the plan. Use the `question` tool with free-form feedback. If the user excludes items or changes the target, rerun the dry-run and show the changed actions. Repeat until the user selects **Confirm restore**.

### Step 3 — Supply secrets, then apply files

If the plan lists missing secrets, create a temporary JSON file mapping each `<REDACTED:label>` label to its value and pass it with `--secrets "<secrets.json>"`. Prefer environment variables for `{env:...}` references. Then run the helper with `--approve "<plan-hash>"`. The helper refuses to write while a placeholder is unresolved, and backs up replaced files/directories under `<config-dir>/.restore-backups/<timestamp>/`.

The dry-run also reports symlink/junction targets. Backups follow the link. `skills-root` and `plugin-data` items merge through the link and keep it; other files/directories replace the link with a real item. Confirm this with the user before applying when link identity matters.

### Step 4 — Install server plugins

For each manifest **extension** with `type: "plugin"`, `classification: "installable"`, and `surfaces` containing `"server"`:

- Run its `install_cmd` (normally `opencode plugin add <spec>`).
- If it fails, record it and continue. Do not roll back the restored config; the declaration is still valid for a later install.
- TUI-only plugins (`surfaces` contains only `"tui"`) are already declared in `cli.json`; the terminal client loads them. Do not add them to `opencode.json`.

For local plugin directories copied under `plugins/`, inspect `package.json`. If it declares runtime `dependencies` that are not provided by OpenCode, run the local package manager install (`npm install`, `bun install`, or the package's documented command). Do not copy `node_modules` from the source machine.

### Step 5 — MCP servers

The restored config already contains local and remote MCP definitions.

- Run `opencode mcp list`.
- Preserve `disabled` / `enabled` exactly as restored; do not enable a disabled server.
- `npx`, `bunx`, and `uvx` servers fetch their packages at runtime. Ensure the corresponding package manager is installed.
- Remote servers may need authentication. Use `/mcps` or `opencode mcp auth <name>`; never run an interactive auth command through a background shell where the OAuth callback can be hidden.
- For `manual_actions` of type `mcp`, show the binary name, command, environment, and enabled state, and let the user install it. Do not silently skip it.
- Managed binaries (for example an OpenCode-installed helper server) are intentionally not copied; let OpenCode manage them on the target.

### Step 6 — Auth providers

No credentials are included in this bundle. For each provider in `manifest.auth.providers`:

- If the provider uses an environment variable, ensure the variable is set before starting OpenCode.
- Otherwise run `opencode auth login` (or `/connect` in the TUI) and choose the provider.
- Never ask the user to paste an API key into the conversation; prefer the official login flow or environment variables.

### Step 7 — Verify

Run the following and report the results:

```text
{{verification_commands}}
```

Also verify:

- `opencode debug config` lists the restored config files;
- `opencode plugin list` includes the expected plugin IDs;
- `opencode mcp list` shows each server as connected, disabled, or needing authentication;
- `opencode debug agents` includes the expected custom agents;
- `cli.json` selects a theme whose `themes/<name>.json` exists;
- no restored config contains `<REDACTED:...>`;
- `opencode reload` succeeds.

### Step 8 — Summary

Report:

- files created, overwritten (with `.restore-backups` paths), skipped, and failed;
- server plugins installed or failed;
- local plugins restored;
- MCPs connected, disabled, needing auth, or manual;
- auth providers still missing;
- manual actions still pending;
- any V1 plugin API warnings or version-mismatch warnings.

OpenCode reloads config automatically after a save. Use `opencode reload` (or `/reload`) if a change is not picked up. Restart the background service with `opencode service restart` only when a local plugin's dependencies or native modules changed.

## Failure handling

- **Checksum mismatch**: stop. The bundle was modified or corrupted; do not restore that file.
- **Missing secret**: stop before writing live config. Collect the value into a temporary secrets JSON file and rerun the confirmed plan.
- **Plugin install failure**: record the plugin and continue; the restored config remains declarative.
- **MCP auth failure**: record it; the server stays configured and can be authenticated later.
- **Version mismatch**: if the target OpenCode major version differs from the source, warn. V1 plugin implementations do not run in V2; port them before relying on them.
